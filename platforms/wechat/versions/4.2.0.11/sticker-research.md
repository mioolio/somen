# 4.2.0.11 表情包路径研究

边界：离线 DLL 分析与受控只读观测，不作为可调用发送 ABI 或已完成能力的证明。DLL SHA-256 见本目录 manifest。没有保存账号、联系人、聊天正文、AES key、令牌或内存转储。

## 已定位的 JSAPI 分支

| RVA | 离线证据 | 尚未确认 |
| --- | --- | --- |
| `0x5703030` | 参数解析引用 `jsapiParam`、`encryptUrl`、`md5`、文件是否可作为 emoticon 的错误说明；构造 native queue 闭包 | 输入结构布局、完整所有权 |
| `0x5705730` | 从 emoji XML 提取 md5、下载及缩略图元数据，随后构造下载/发送闭包 | 与 Qt 直接发送是否共用 ABI |
| `0x571b8c0` | `Failed to send emoticon` 错误分支，使用 MessageService，闭包大小 0x68 | 共享模型类型与目标字段语义 |
| `0x571caf0` | 取得 EmoticonService，调用下载相关函数后进入类似发送路径 | 下载回调、资源所有权与超时语义 |
| `0x20f2b70` | `EmoticonService::ClearSearchData` 相关调用 | 不是搜索请求入口 |

两个闭包具有 vtable、回调所有者、两个 std::string 和一对 shared_ptr。闭包片段不等于可独立直接调用的业务接口，不可将猜测对象布局传入这些函数。

## 本次受控观测

用户在目标微信的唯一测试联系人聊天中手动搜索并发送了一张真实表情包。已加载探针仅捕获 `0x20f2b70` 搜索清理调用；上表其他四项均未触发。未获得发送参数或完整发送链。

这说明当前 Qt 操作走的是另一条内部路径，不能将 JSAPI 分支当作本次实测链。此结果不能用于启用 native sticker、在线搜索或收藏添加 capability，也不能把普通图片/GIF 消息作为 type 47 替代品。

## 其他静态候选

`0x212e670` 从 Emoticon 模型拷贝 DTO，调用者包括 `0x4ad9530`、`0x20e7c60`、`0x211e510`、`0x9d64b0` 与上述下载/发送闭包。它本身不是发送入口。

部分 Qt 调用者经过 `0x20ef5b0` 构造任务；该函数接收一个 shared_ptr 和整数，没有显式收件人，可能负责使用记录、收藏或 UI 状态。其闭包 invoke 是 `0x210afa0`，再调用 `0x20ee1f0`。没有通过运行时观测确认其实际业务，因此不能盲调为发送。

下一步需要独立核对 Qt 实际 slot→service→发送入口、当前账号及目标校验、参数类型、回调寿命、下载完成与消息 type 47 回显，再决定可复用 API。原生会话及观察器必须保留 referenced worker 到微信退出，不能为重新布置探针强杀或卸载旧会话。
