# Windows 探测适配器

边界：本目录仅采集微信进程元数据、当前账号标识及活跃账号目录线索。不提供通信、自动发送、数据库读取、密钥提取或进程写入。

## 文件职责

- `scan.ps1`：一次 CIM 进程快照、角色分类及结果组装，使用 Windows 自带的 64 位 Windows PowerShell。
- `ProcessMemory.cs`：有大小上限的只读内存访问及进程创建时间核对，所有进程句柄释放。
- `CurrentAccount.cs`：通用的当前账号管理器读取器，保持版本、散列、代码与类型校验。
- `AccountProfile.cs`：版本配置的类型契约与范围校验，不包含具体版本偏移。
- `load-profiles.ps1`：自动加载 `../versions/*/identity.json`，单个配置损坏仅产生诊断，不影响其他配置。
- `../versions/4.2.0.7/identity.json`：此版本独立的散列、RVA、vtable、结构偏移与 getter 代码字节。
- `ActiveFileHandles.cs`：未知版本的保守降级，仅观察指定 PID 已打开的磁盘文件路径；目录名保留原样，作为未验证候选。

`Add-Type` 在运行时加载这些源文件，不需要安装 C++ 编译工具或生成项目发布包。Node 桥接层在 `../server/probe.mjs`，负责异步调用、20 秒超时和 4 MiB 输出上限。

## 当前账号适配范围

当前已验证：Weixin **4.2.0.7 / 4.2.0.11 x64**。下面保留 4.2.0.7 初始研究记录；新版精确数据见各版本目录。4.2.0.7，`Weixin.dll` SHA-256 为：

```text
9beb1051449e768417d770915646815a5bd1899cc2779f758069820794358ee0
```

读取链：`*(moduleBase + 0xbcf4d70)` 为 manager，`*(manager + 0x68)` 为当前账号 owner，owner `+0x48` 为 MSVC `std::string` 账号标识。这里不是搜索内存或枚举历史账号对象。

读取前校验 DLL 版本和散列、当前账号 getter 代码字节、manager 与 owner 的 vtable、getter 虚函数槽、共享指针引用计数、字符串边界及终止符。读取后复核指针及账号内容，进程句柄的创建时间必须与元数据快照一致。CIM 与进程对象的创建时间必须在 CIM 的微秒精度内一致，否则跳过该进程；目录候选的独立进程句柄同样核对创建时间。任一账号检查失败即返回待识别状态。

WeChat 3.x 及其他 Weixin 4.x 版本仍可识别进程；确切账号读取需补充各自独立、经验证的适配。活跃目录候选不等于当前登录账号，不删除目录后缀，也不将候选升级为已验证账号。

## 参考与验证记录

账号结构参考本机 `AGI/WXcc/agents/read-native-4.2.js` 的 `accountData`；manager 指针链经相同版本 DLL 离线反汇编与只读实机核对确认。未复制发送、聊天内容或密钥读取实现。

2026-10-30 本机只读验证：5 个 `Weixin.exe` 进程归为 1 个主进程与 4 个带 `--type` 的辅助进程，4.2.0.7 当前账号校验成功，无诊断警告。完整扫描约 1.5–1.8 秒；账号值和本机路径未写入仓库。

添加相同读取结构的版本适配时，在 `versions/<version>/` 增加一个独立 `identity.json` 即可，无需修改读取器或注册列表。删除或放回配置文件会在下次扫描生效；删除整个配置目录仍保留进程识别及未验证目录候选。每个文件须提供 `schemaVersion: 1` 与 `reader: current-manager-msvc-string-v1`，完整填写 DLL 名称、版本、x64 架构、SHA-256、指针布局和至少两个代码检查，getter 本身及账号入口都必须覆盖。RVA/偏移使用十六进制字符串，代码字节使用空格分隔的十六进制字节。配置损坏、重复或越界时不会读取不受信任的偏移。

结构不同的新版本需要先实现单独的读取器契约，不能仅用相近版本号复用偏移。所有适配必须记录独立的 DLL 散列、指针结构、代码字节验证及实机验证结果。
