# 架构与边界

## 分层

`tools/dev.mjs` 组合 Node HTTP 宿主和 Vite 开发中间件，一个地址提供网页与 API。只绑定 `127.0.0.1`，通过 Host、Origin、Fetch Metadata 校验限制外部网页读取本机数据。

`kernel/` 没有具体平台的静态导入，不负责进程识别或账号解释。自动发现 `platforms/*/manifest.json`，为每个插件分配独立 API 命名空间。加载失败回滚其路由、释放注册资源，其余插件继续加载。

`apps/panel/` 提供布局、导航、页面插件发现与空宿主页面。每个平台在自己的 `panel/register.js` 和 `panel/routes.js` 声明页面；组件延迟加载。前端只启用后端成功加载的平台，目录移除后无需清理硬编码列表。

`platforms/wechat/` 拥有微信所有具体实现，包括 API 注册、扫描调度、进程归类、Windows 探测和页面。扫描通过异步子进程执行，不阻塞 Node 事件循环。并发请求合并，短期内复用成功结果；错误不伪装成零实例。

## 可拔插的含义

可拔插单位是 `platforms/<id>/` 整个目录；重启宿主生效。`enabled: false` 可禁用插件。平台内部功能通过独立文件与明确导出分离，替换文件遵循导出契约。删除平台必需文件只禁用该插件，不影响其他插件与壳层。

宿主、公共依赖和功能导出仍有明确契约。“任意删除任意文件而全部功能不变”不成立；这里保证平台间隔离、加载失败隔离与单功能可替换。

当前为模块、路由、数据、生命周期隔离，不是恶意插件安全沙箱。插件运行在同一个 Node 宿主，耗时原生探测在有超时的子进程中。未来不可信第三方插件可升级为进程级宿主。

## 约束

根目录四个非 Markdown 文件分别承担依赖声明、锁定、忽略规则、授权职责。配置与启动在 `tools/`。每源文件最多 2000 行；职责注释、体积、根目录数量与依赖方向由 `npm run check` 检查。

只支持 Windows。跨系统贡献应提供新 OS 适配器及测试，避免内核理解平台系统差异。本轮无生产构建或部署。
