# 2026-10-30 · 工作实例选择修复

点击“设为工作”时，旧服务把原生回调所有权仍需保留误判成不能选择；失败又保留了暂停状态，重复点击进入同一拒绝路径。上一个阶段只更新了源码，未刷新仍在运行的后端，因此旧行为继续存在。

- 选择实例只绑定经只读扫描确认的 PID、启动时间和账号。旧运行立即从业务引用中剥离，独立模块在后台收尾，保留、旧协议返回、失败或无响应均不拒绝新选择。
- 原生接口在请求收尾的同步阶段停止接受业务操作，收尾请求幂等。失去 IPC 或 worker 退出不能作为微信进程已退出的证明；不终止 worker、不卸载原生脚本。
- 同一精确身份的重复选择保留工作上下文；监控曾中断而身份重新确认时，只恢复监控，不重建原生运行。
- 已有发送结果未确认时，选择仍可进入工作；发送暂停和回执按精确身份保留，离开再返回也不会解除。新工作不会沿用上一个工作目标。
- 原生事件及后台收尾事件保留创建时的匿名会话引用和代次，旧事件及其日志失败不能中断新工作。
- 前端每次点击提交选择意图，按返回绑定确认成功，不把原生发送是否就绪作为导航条件。
- 删除“识别依据”、来源及候选证据展示，并清理无用格式化函数和样式。

验证：`npm test` 95 项通过，`npm run check` 和 `git diff --check` 通过。合成测试覆盖旧协议保留值、同步失败、异步失败、收尾无响应、重复选择、未知发送结果及跨实例返回。

本地开发服务已刷新，4 个已有原生所有权进程继续存活；连续两次选择当前已确认实例均返回 HTTP 200、精确绑定及 active。开发服务实际提供的 Vue 组件和选择模块均返回 HTTP 200，组件不再包含“识别依据”。这次验证没有新增原生附加、读取联系人或发送消息，没有运行生产编译。
