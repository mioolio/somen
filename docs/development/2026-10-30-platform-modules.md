# 2026-10-30 · 平台选择器与工作模块

用户要求前端区分平台选择器与工作，工作入口应放在微信平台下面，并为后续多个平台保留独立边界。

- 通用导航支持插件父项和模块子项。微信插件声明“平台选择器”和“工作”，壳层只读取注册，不判断具体平台名称或 ID。
- 面包屑根据当前注册平台及模块解析，活动项按实际模块匹配，不因父路径前缀让多个模块同时选中。
- 平台选择器中“设为工作”绑定已验证实例，成功后进入工作。已选的同一实例直接进入，不重复选择或重建原生会话。
- 工作页仅显示已选上下文、联系人、发送、表情及日志，删除重复的账号下拉选择和切换逻辑；返回选择器使用独立模块入口。
- 服务端对同身份的选择幂等。切换实例时，只有旧原生运行明确业务静默或已结束才继续；静默但保留回调所有权的进程继续独立存活，不物理卸载。
- 通用导航测试使用两个不同的虚构平台及子模块，验证跨平台路径隔离、旧单入口兼容、精确活动项与路由归属。工作选择回归验证幂等、静默所有权保留及旧事件隔离。

本轮只调整代码、注册和工作选择语义，没有自动操作微信窗口、读取新联系人、发送消息或新增原生附加。不运行生产构建。以 main 阶段提交保留回溯。

验证结果：`npm test` 79 项全部通过，`npm run check` 通过；通用导航 SSR 验证父子模块、单一活动项和面包屑。选择协议用合成请求验证同实例 GET-only、不同实例一次 POST、失败不导航。保留已停止的 Computer Use 状态，不为此次前端调整操作真实账号。
