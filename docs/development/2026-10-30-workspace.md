# 2026-10-30 · 工作微信与受限发送

## 用户授权与范围

用户指定截图中的微信账号作为工作账号，授权读取该账号联系人，并仅对其唯一普通联系人测试文字、图片、表情和表情包。账号及联系人实际标识只保存在忽略的本地状态，不写入代码或提交。用户随后确认另一个微信已退出。

本阶段沿用 main 和既有用户提交身份。参考 AGI/WXcc 只读提取已验证的 4.2.0.7 联系人/文字/图片实现，拆分为本平台版本模块；未修改参考仓库。

## 架构

- 工作账号绑定 PID、进程创建时间、账号 ID；发送前重新核对，不按昵称或 PID 单独选择。
- 独立监控每 10 秒跟踪；状态失效立即关闭发送，继续收集延迟崩溃记录，不自动换号或重发。
- 日志在 `.local/wechat/` 轮转，默认记录事件、异常类型、匿名会话标识及必要代码，排除正文、真实账号、联系人和机器路径。
- 原生运行时在独立持久子进程，API 串行，未知结果关闭后续发送。发送前在本地账本持久化 requestId 与内容/身份指纹，避免重启重复发送。
- 用户强调跨版本兼容为核心：统一放在 `platforms/wechat/versions/<version>/`，每个版本独立保存 manifest、身份偏移、校验与原生代码；不在通用模块混写版本偏移。

## 已观察到的问题

4.2.0.7 联系人读取成功，缓存 7 项，其中唯一普通联系人符合用户描述；缓存 `complete:false`，不宣称完整通讯录。

随后原生探针尝试卸载/断开后，选定微信在数秒内崩溃。Windows Application Error 1000 与关联 WER 1001 已精确按进程生命周期归属并脱敏保存。异常 `0xc0000005`，模块 `ntdll.dll`，偏移 `0x165497`，对应 `__chkstk + 0x37`。该证据不足以单独证明卸载是根因；仍需运行栈/转储进一步定位。

已移除主动 `script.unload` / `session.detach` 路径。业务停止后保留独立回调宿主到微信自然退出，避免把“任务数为零”误当作原生回调引用已清空的证明。此为可疑生命周期路径修正，不能据此宣称崩溃根因已完全解决。

重新打开后，客户端自动更新为 4.2.0.11。旧版指纹拒绝执行，新版按独立目录重新比对。各阶段实际验证结果将在后续提交追加；未验证的发送或表情能力不标为成功。

## 新版阶段验证

4.2.0.11 的身份适配经过 RTTI/COL、RIP 引用与只读 RPM 验证；原生联系人/发送 21 项函数经代码、调用关系、数据结构与具体常量核对。图片入口的四处差异确认为源码日志行号变化，未按相近版本直接复用偏移。静态证据与实机证据分开放在版本目录。

受控原生运行连续约 10 分钟未发现新崩溃；唯一联系人绑定通过。文字和图片各测试一次，客户端返回 accepted，并分别在目标聊天看到测试文字与蓝色 PNG。保持 `deliveryConfirmed:false`，没有把聊天回显视为服务端回执。请求和媒体仅存 `.local/`，没有重复发送。

内置表情：从精确 DLL 的 Qt RCC、真实面板 XML 及中英文指针表解析 109 项，含真实 PNG、token、中文及英文名；中文“微笑”与英文“facepalm”搜索均验证命中。官方素材仅运行时从本机读取，不提交到仓库。

目前 61 项自动测试及 `npm run check` 通过，覆盖持续跟踪、崩溃归属、隐私日志、版本分离、HTTP 正文边界、图片完整解码、唯一联系人、代次隔离、关闭竞争及跨宿主去重。仍在单独验证 type 47 表情包、收藏和在线搜索，不宣称已经完成。

## 面板重启后的第二次崩溃与保活修复

重启开发面板后，4.2.0.11 出现第二次访问冲突，Windows 明确记录 `frida-agent.dll_unloaded + 0x9c7e0`。仅保留 JavaScript 对象且不调用 unload/detach，并不足以保持 Node 子进程存活：IPC 断开且没有活跃事件循环句柄时，进程仍会自然退出，进而卸载 agent。

原生 worker 现由独立 `worker-host.mjs` 管理，加载前即持有明确的 referenced 定时器，父进程失联后继续保留；目标微信进程明确终止后才解除保活。fork 使用独立进程组并隐藏窗口；stdout/stderr 的 EPIPE 不触发未处理异常。致命 JavaScript 异常停用业务能力但保持回调所有权。

新增真实进程回归：启动无 Frida 的测试父/子进程，强制终止父进程后子进程仍存活，直到模拟目标终止事件才退出。该测试验证事件循环和 IPC 生命周期，不把它伪称为新的微信稳定性实测。崩溃日志现保留 `_unloaded` 模块标识及故障偏移，便于后续诊断。

初始化异常后的 session/script 另由常驻所有权集合持有强引用，避免局部变量消失后被回收。普通连接断开、设备丢失、应用请求等原因不视为目标进程死亡；只有明确的 `process-terminated` 允许释放。对应工厂失败与六种生命周期回归已通过。

## 本轮停止点

重新登录同一工作账号后，内置微笑 token 通过本项目 API 提交，聊天中显示为真实表情图标。工作页面和中文搜索已在实际浏览器验证；当前共 109 个真实内置项。

真正的 type 47 仍在研究。用户按约定进行了两次表情包操作，但初始 JSAPI / Qt 探针没有获得经过目标匹配的完整发送参数，不能据此启用发送或收藏能力。精确 CGI、MMUI 与 Qt 线索分别写入版本研究记录，业务能力维持不可用。在线搜索与收藏枚举/添加也未宣称完成。

用户通过物理 Escape 停止 Computer Use 后，停止所有后续界面操作和真实发送，保存现有阶段。持续监控和回调宿主保留，不通过强杀原生宿主清理。最终 `npm test` 共 69 项通过，结构检查通过；无生产构建。真实账号、联系人、媒体、运行快照和原始观测仅位于忽略的 `.local/`。
